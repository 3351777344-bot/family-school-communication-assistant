# 家校沟通助手 · 原型 v2 启动说明

三个文件，一个服务，不用装任何依赖。

| 文件 | 作用 |
|---|---|
| `server.js` | 本地服务：发网页 + 替网页调 DeepSeek + 脱敏与后置校验 |
| `kb.json` | 知识库（10 条）。模型回答时的"依据"来自这里，可以随时改、加、删 |
| `家校沟通助手_原型v2.html` | 页面本体（表单 + 四块结果 + 继续讨论） |

## 二、key 放在哪

程序按这个顺序找：

1. 环境变量 `DEEPSEEK_API_KEY`
2. 文件 `C:\Users\ASUS\Desktop\api.txt`（可以直接放 key，也可以写成 `DEEPSEEK_API_KEY=xxx`）

**三条注意**：

- key 只在服务端，网页里没有。别人用浏览器看源码也拿不到。
- 不要把 `api.txt` 发群里、不要传网盘、别提交到 git。
- 想换个位置：`set KEY_FILE=D:\keys\ds.txt && node server.js`

## 三、接口（以后换前端、换飞书，都照这个契约）

### `GET /api/health`
返回服务状态、模型名、key 是否读到、知识库条数，并 ping 一次接口。

### `POST /api/prepare`
请求：
```json
{
  "scene": "xueye",
  "sceneName": "学业警示",
  "situation": "某学院大二学生，缺课12节……",
  "parentReaction": "已沟通但不认可",
  "studentWish": "要求对父母保密",
  "chips": ["要求保密"],
  "stage": "已上报与研判",
  "extra": "家长情绪容易激动"
}
```

返回 `data`：
```json
{
  "sceneName": "学业警示",
  "points": [{"title":"", "why":"", "source":"rule|know|adv",
              "detail":{"aim":"","why":"","react":[],"reply":""}}],
  "steps": ["", "", "", "", ""],
  "risks": [{"title":"","detail":""}],
  "draft": "给家长的底稿，危机场景为 null",
  "faq": [{"q":"","a":""}],
  "next": ["", "", "", ""],
  "crisis": false,
  "notes": "",
  "flags": ["系统自动处理了什么"],
  "redacted": ["手机号"]
}
```

### `POST /api/chat`
请求：`{ message, history:[{role,content}], input:{scene,sceneName,situation,parentReaction,studentWish} }`
返回：`{ ok, reply, redacted }`

## 四、三层保护（对应验收里的否决项）

| 层 | 做什么 | 对应 |
|---|---|---|
| 发送前 | 手机号、学号、身份证、邮箱自动替换成 `[手机号]` 之类 | F2 |
| 输出后 | 命中"抑郁/焦虑/确诊/患有"等词，就地替换并记录 flags | C4、D3 |
| 输出后 | 提到处分/上报/休学但没写"由谁决定"，底稿直接作废 | C2 |
| 场景 | 危机前期强制 `crisis=true`、`draft=null`、流程只留第一步 | C5 |

前端会把这些处理结果显示在结果区顶部的灰色条里，辅导员看得见。

## 五、改哪里会影响到什么

| 想改 | 改哪里 | 会不会影响别的 |
|---|---|---|
| 回答的规则、口径 | `server.js` 里的 `systemPrompt()` | 影响所有场景 |
| 增加依据/资料 | `kb.json`（照现有字段加） | 只影响用到那条的场景 |
| 换模型 | 启动时 `set MODEL=xxx && node server.js` | 前端不用动 |
| 换整个模型服务商 | `API_BASE` 环境变量 | 前端不用动 |
| 改页面 | `家校沟通助手_原型v2.html` | 接口契约不变 |
| 加图片上传 | 新增 `/api/prepare` 的多模态分支 | 契约加一个字段即可 |

**这三行是"能迁移"的关键**：前端只认那套 JSON，模型和知识库都在后面，以后换成飞书、换成别家模型，只换一层。

## 六、已知限制（别当成 bug）

- 没有登录，谁打开 127.0.0.1 都能用——目前只在本机，不对外。
- 对话记忆只在当前页面，刷新就没了。
- 不支持图片（下一步）。
- 一次生成要 3—10 秒，因为真的在调模型。
- `kb.json` 里大部分条目标着"待审核"——**这些内容在拿到陈老师确认前，只能当参考，不能写进对外材料**。

## 七、下一步（按优先级）

1. **补知识库**：把组员那份资料清单加工成 `kb.json` 的格式（场景 / 做法 / 来源 / 审核人 / 状态），这是唯一直影响回答质量的事。
2. **图片上传**：`deepseek-flash` 支持传图（PNG/JPEG，单图 32MB），加一个 `/api/prepare` 的多模态分支即可；上传前要提醒"别传带姓名和家长头像的截图"。
3. **记录试用数据**：每次生成后记录"改了几处""用了没有"，攒够 500 条再谈微调。
