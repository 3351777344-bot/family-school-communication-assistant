# 家校沟通助手

面向高校辅导员的家校沟通准备原型。项目当前处于可演示和本地模型联调阶段，不是可部署的正式业务系统。

开发方向、原型交付清单与验收标准见 [完整开发方案](docs/product/家校沟通助手_完整开发方案_2026-11-11.md)。现有模型质量对照见 [场景评测](evals/README.md)，资料准备见 [模型资料准备模板](docs/research/模型资料准备模板.md)。

## 目录

- `apps/web/`：React + TypeScript 工作台，包含组件、状态、样式与前端回归。
- `app/`：Node.js API 服务、知识库和保留的两种 HTML 原型。
- `scripts/`：启动、模型预检与本地界面测试工具。
- `tests/`：服务端配置、输入、模型调用与静态资源回归。
- `dist/web/`：前端构建产物，自动生成，不提交版本库。
- `docs/product/`：交互设计稿与技术边界。
- `docs/trial/`：试用说明、试用流程与验收标准。
- `docs/research/`：资料清单及处置结论。
- `docs/meetings/`：会议纪要、行动项和记录表。
- `docs/handoff/`：待确认事项及工作提示。
- `archive/legacy-prototype/`：历史原型和旧知识库，仅供追溯。

## 启动与API配置

需要 Node.js 22.12 或以上版本；当前本机为 Node.js 24。首次进入项目先运行 `npm ci` 安装锁定的依赖。根目录 `.env` 由用户维护，服务启动时读取；现有 Shell 环境变量优先。`.env` 已被 `.gitignore` 排除。公开配置模板见 `.env.example`，不含密钥。前端不加载根目录 `.env`。

1. 在 `.env` 填写 `DEEPSEEK_API_KEY`。需要千问对照时可另填 `DASHSCOPE_API_KEY`。
2. 项目默认使用 `AI_PROVIDER=deepseek`、`DEEPSEEK_MODEL=deepseek-flash`，关闭深度思考。手动选择千问时，设置 `AI_PROVIDER=qwen`，使用 `QWEN_MODEL/QWEN_API_BASE`。
3. 初始 `MOCK=1` 只显示离线示例。填写密钥不会自动发出模型请求；需要真实生成时改 `MOCK=0` 并重启。
4. 在项目根目录运行 `npm start`，会先构建新版前端，再启动 `http://127.0.0.1:8787`。`npm run start:mock` 强制离线，也会先构建。直接 `node app/server.js` 不构建；没有构建产物时保留旧原型兼容入口。
5. 资料选取有三个可选项：`SOURCE_TIERING`、`MAX_SOURCES_PER_MOVE`、`EXPOSE_APPLICATIONS`。默认值已够用，一般不用改；含义与取值范围见 `.env.example` 和 `app/config.js` 的 `SOURCE_DEFAULTS`。取值非法时服务启动即报错。

前端开发另开终端运行 `npm run dev:web`，开发页通过代理访问 8787 的 API。`npm run typecheck` 检查类型，`npm run build:web` 构建，`npm test` 运行前后端本地回归。架构、状态与界面测试说明见 [`apps/web/README.md`](apps/web/README.md)。

模型连通性检查只发送一条虚构技术提示，不发送项目资料：

```powershell
npm run model:check -- --provider=qwen
npm run model:check -- --provider=deepseek
# 只预检指定的质量对照快照，不改变.env中的日常模型
npm run model:check -- --provider=qwen --model=qwen3.8-flash
# 只检查配置存在性，不请求模型
npm run model:check -- --dry-run
```

此命令的真实检查可能产生API费用，输出仅含状态、模型和usage，不包含key或模型原始回复。模型权限、地域和思考/JSON参数兼容性按账号实际结果确定。`GET /api/health` 只说明本地配置状态，不主动调用模型，也不将“已配置”等同“已连通”。

配置变更后需要重启。真实模式缺少密钥会返回503；模型失败时保留输入和旧结果，不替换成固定示例。`npm test` 运行本地桩与配置回归，不调用外部模型。

## 数据与隐私

服务监听在本机回环地址，但模型联调版会把表单内容发送至配置的模型服务。学校平台的访问权限、日志和保存期限，以及模型服务方的数据处理规则均待确认。请勿输入真实个案、姓名、学号、班级、咨询原话或可识别家庭信息。

服务端会在发出请求前替换部分手机号、身份证号、学号、邮箱和座机格式。要点和家长底稿由模型书写，因此服务端在接受结果前会检查：底稿出现诊断性表述（抑郁、焦虑、确诊等）或处分、上报、休学、档案等表述时直接拒绝并要求重写一次；底稿中出现的每个数字必须能在输入原文中找到；用于个案事实的原文片段必须逐字取自输入。它不能可靠识别人名、班级、关系描述等所有身份信息；自动替换不构成匿名化保证。试用请使用虚构场景。

## 当前产品边界

仅提供辅导员沟通准备参考。系统不判断危机等级、不决定是否告知家长、不提供诊断或处置方案、不自动发送信息、不建立个案记录。危机场景入口暂时禁用，待校内确认触发方式和提示口径。

学生要求对家长保密、或只说想先和学生核对时，系统不再暂停底稿，而是在输入区和结果区给出提示。是否告知家长由辅导员判断，系统不代为确认可告知范围，也不把生成内容视为已获准对外披露。

## 尚待校内确认

- 学业警示及心理危机相关流程、依据和审核人。
- 危机提示是否纳入演示、触发条件和联系入口。
- 数据访问、日志、保存期限和刷新后的数据行为。
- 五步流程正式名称、产品正式名称和验收适用范围。

## API

- `GET /api/health`：返回运行模式、模型、密钥读取状态和知识库条数。
- `POST /api/prepare`：脱敏表单字段并生成结构化沟通准备结果。

自由聊天接口已从当前版本移除，以符合交互稿范围。详细启动说明见 [`app/README.md`](app/README.md)。
