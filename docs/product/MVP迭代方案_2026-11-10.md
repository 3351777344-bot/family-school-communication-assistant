# 家校沟通助手 MVP 迭代方案

版本：2026-11-10。本方案是开发与评审依据，不表示已经完成架构迁移、模型接入或训练。

## 1 目标与范围

目标：辅导员能在一个工作台，用已核实且不含可识别信息的背景，获得有依据、可修改、可核对的沟通准备，并决定是否采用。

首版覆盖：学业警示/在校情况、心理健康首次告知/就医认知、一般家校沟通；家长不认可、情绪激动、隐瞒、不配合、学生希望保密作为交叉条件，不扩大成不同使用端。危机场景只保留经中心确认的人工核实提醒，正式演示入口在确认前禁用。

按原型稿完成 P0使用边界、P1工作台、P2四类核心结果、P3详情抽屉、P4底稿编辑核对预览复制、P5人工协助提示、P6可选后续事项，以及E1信息不足和E2安全提醒。家长/学生账号、自动发消息、个案历史、心理测评和线上展览不纳入此次MVP。

交付分两道门槛：先完成虚构场景下的可用性MVP；只有学校与模型服务的数据处理规则确认后，才讨论真实业务试点。

## 2 当前差距

详细实测见 ../reviews/2026-11-10/实测记录.md。此次已启动MOCK并点测，不代表已验证真实模型质量。

立即处理：底稿折叠丢稿；模型失败回退固定例子；过时模型名；简单词表误伤正常流程；信息不足靠字数；来源只挂类型标签；页头与双滚动；输入自动收起后难以核对。

旧《技术边界与选型建议》对8B能力和“必须拿到保密案例”的表述是未经本项目实测的早期判断，不能作为事实结论。现有8B模型可以作为可替换基线评测，是否保留取决于结果；学校保密案例不是MVP前置资料，不取得、不入库同样可以先推进公开材料与经审核经验卡片。

## 3 模型选择

按用户当前账号额度，产品内AI agent首轮主候选改为 qwen3.8-flash，小批量质量对照使用固定快照 qwen3.8-max-0902，DeepSeek deepseek-flash作为跨服务商对照。两款千问3.8均已通过单次真实JSON预检；尚未进行领域盲评，不宣称哪家更懂辅导员。

此前按官方目录提出的qwen3.7-plus建议已被账号实际额度约束替代；用户提供的控制台截图列有3.8系列免费额度且启用“用完即停”，该控制台设置保持不变。额度余额与到期时间以用户控制台实时状态为准。DeepSeek官方2026-10-17更新说明 deepseek-flash 指向最新V4.1 Flash；deepseek-chat/deepseek-reasoner已公告停用。账号实际地域、额度、模型权限和可用ID必须通过该账号预检确认。

主模型负责结构化要点与底稿；第二家模型先用于离线对照。MVP不默认每次双模型调用，也不把第二个模型的审核当作通过安全验收。模型故障不自动切到另一家传输同一输入，需明确批准可用的服务方和路由策略。

模型适配器负责不同服务商的 endpoint、model ID、结构化输出、流式接口、思考参数、usage、finish_reason、超时和错误码。JSON Object只保证合法JSON，不代表字段、类型、引用或事实正确；仍需schema和业务校验。各模型的思考模式与JSON兼容性要分别验证，不能只改API_BASE就认定兼容。

密钥从环境变量/项目外密钥文件读取，只在服务端使用。先提供服务商、地域、模型ID及本地密钥文件路径；不要写进方案、截图、日志或版本库。实际调用前预检模型权限与费用设置。

## 4 架构与工程结构

采用模块化单体。建议前端 React + TypeScript + Vite，后端 Node.js + TypeScript + Fastify，公共协议用JSON Schema或Zod统一。保留HTTP接口，避免一次引入微服务、多智能体调度和复杂平台框架。

建议结构：

```text
apps/web/                 页面、组件、状态、交互检查
apps/api/                 路由、鉴权、限流、请求生命周期
packages/contracts/      输入输出schema、错误码、来源契约
packages/ai/             DeepSeek和千问适配、提示词版本、生成编排
packages/knowledge/      检索、审核状态、来源与版本校验
packages/safety/         隐私检查、字段边界、人工核实分支
knowledge/sources/       授权来源元数据
knowledge/cards/         经审核的知识卡
prompts/                 场景模板及版本记录
evals/cases/             虚构评测场景与参考要点
evals/runs/              经批准保存的脱敏评测结果
docs/                    产品、实测、资料和交接说明
archive/                 旧原型留档
```

当前app/作为迁移来源，逐模块替换，保持可运行。增加Git基线、依赖锁定、环境变量示例、启动脚本、格式检查与CI；先建立接口契约和关键E2E，不为了目录层级拆服务。

数据方面：小型知识库先用JSON/SQLite保存公开/获准知识卡元数据与检索索引；SQLite不保存真实个案。候选为关键词/全文检索加场景过滤，只有召回评测证明必要时再加向量检索及重排。多人内测前接入学校允许的身份验证和服务端权限；输入正文不写应用日志，调试和评测数据有单独授权与保存规则。

生成链路：输入schema验证 → 自行去标识与字段提示 → 缺失事实检查 → 安全提醒分支 → 已审核资料检索 → 一次结构化生成 → schema/事实/引用/边界校验 → 需要时一次受控修复 → 返回可核对结果。安全提醒能在模型调用前确定时，直接返回人工核实卡，不再让模型生成处置内容。避免自由规划工具和无限重试。

## 5 前端迭代

P0：底稿文本、原稿、编辑状态、四项核对、确认版本和后续勾选均进入统一页面状态；折叠只改变可见性，不重建数据。修改任一字使旧确认失效；还原草稿、替换结果和刷新提示符合已确认的数据规则。建立“编辑→确认→折叠→展开→复制”回归用例。

P0：请求期间禁用重复提交，支持取消、超时、重试；失败保持用户输入和上一份结果，显式显示失败。固定示例只存在演示入口，真实生成失败不替换成示例。健康状态区分“模拟/已配置/已验证可用/故障”，不能只读到key就显示已连模型。

P1：桌面左输入右结果，核心四块默认可浏览；常见问题和后续事项为次级区域。输入默认保留可核对视图，窄屏改横向“查看输入”条，页头精简，避免内外双滚动。参考测试尺寸1440×1000与390×844。

P1：场景切换保留输入但标出旧结果所属场景；重新生成使用应用内确认框，保留旧底稿直到新结果成功。来源在要点旁显示出处和审核状态，详情抽屉提供具体支撑片段；区分“你提供的事实/公开知识/沟通建议”。仅已审核来源可显示“校内流程”。

P1：E1根据缺少年级/触发事件/家长反应等语义槽位给出补充提示；非空短输入也可进入明确标记的通用参考，不用6/15字阈值作理解判断。表单补齐label、键盘操作、焦点管理、抽屉关闭后焦点返回。

## 6 回复质量改进

### 6.1 事实与来源

输入先形成事实清单并由辅导员确认；系统不能把任意输入自动标成“已核实”。事实以ID传给生成器，底稿中的具体事实须能映射到输入事实。未提供“谈过两次”“已联系任课老师”等动作，不得补写。取消“XX老师好”“孩子没事”“不是坏事”等无条件固定措辞。

输出的每个制度性建议携带source_id、版本、支撑片段和审核状态。代码验证引用ID真实存在、该条已审核且适用本场景；是否真正支撑建议需人工抽检/评测，不能只验ID。没有学校流程时说明限制，不凭通用知识编造条款或期限。

### 6.2 区分知识与表达

资料回答“依据什么”，场景模板回答“按什么结构说”，模型负责整理、改写与有限表达建议。三类场景分别约定必须覆盖项、可选项、禁入项和信息不足处理，不能一套学业模板套所有场景。

安全校验区分流程标题、一般知识、否定性说明、家长引用、AI建议和对外底稿，避免出现“谈到某疾病名就删词”“流程含上报就替换整句”的误伤。确认越权建议时拦截对应字段或整份底稿并说明原因；不通过粗糙替词拼出一段失去语义的成稿。上下文模型审核只做补充信号，不取代确定性检查与教师审核。

### 6.3 评测与反馈

先由20张虚构场景卡试跑两个候选，每张重复3次，定位错误类型；再冻结100张覆盖矩阵：学业30、心理首次告知25、家长冲突20、信息不足15、安全提醒与越界诱导10。场景之间交叉覆盖保密要求、否定句、身份线索、诱导编造和制度缺失。

每例给参考要点、允许事实、依据、禁答项和人工分支；不只准备一段“标准话术”。用同一输入、同一已审核知识卡、同一输出schema比较候选，匿名随机排序，由两位领域审核者独立评分，争议交陈老师确认。模型自评只辅助排查。

建议MVP工程门槛（待项目组确认）：100例冻结集首次结构有效率≥99%；事实杜撰、伪造制度依据和严重越权在此集合中为0；来源ID有效率100%、引用内容支撑率人工抽检≥95%；关键知识召回Recall@5目标≥90%；重复运行稳定性、延迟P50/P95、每次token与成本全部记录。建议常规请求P95≤20秒为优化目标，实际通过账号测量后调整。上述0错误仅描述有限评测集，不证明现实中绝不出错。

业务验收沿用已制定问卷：2—3位辅导员、有效演练≥6次；六项否决项任一≤2分即不通过；加权总分≥4.0且各模块≥3.5。虚构场景只验证演练可用性，不能直接证明真实工作节时。增加“底稿改动处数、事实修正次数、被误导次数、是否愿意采用”反馈，先不记录个案正文。

## 7 书目与资料处理

新文件是六本推荐书的目录：家庭评估、家庭的秘密、鲍文家庭系统治疗、家庭与家庭治疗、心智化家庭治疗、心智化手册。已归档到 ../research/陈予推荐书目.docx。书目未附正文、版次页码，使用条件列为空；作者译名与版本尚待核对。本方案未把推荐目录视为已掌握书籍内容或已获入库/训练许可。

建议请陈老师从推荐书中选与辅导员沟通准备直接有关的少量章节，提供自己的原则总结、出处页码、适用范围、常见误用及可用表达，先做10—20张审核知识卡。家庭治疗理论只用于经审核的沟通理解与表达原则，不用于给家庭下结构性诊断或建议治疗。

校内流程比书籍数量更紧急：学业警示流程、允许公开的职责分工、心理中心求助入口、保密与告知的审核口径，以及五步流程的适用条件。资料使用范围要分别注明“可人工阅读/可检索引用/可外部API处理/可训练”，四者不能互相推定。

## 8 是否训练以及怎么训练

MVP先做API基线＋审核知识库＋场景提示词＋评测。书籍属于知识来源；直接整本训练既难以更新溯源，也不自动教会辅导员视角。学校制度更新应在知识库维护。

当同一批错误在完善提示词、检索和输出契约后仍稳定出现，例如总是写成长文、不会适度追问、难以遵循固定表达结构，再评估SFT。API key不等于模型权重、微调权限或该型号支持训练；选择百炼当时支持且账号可用的可调优基座，另行核对费用、部署限制与导出条件。DeepSeek推理API与本地训练开源权重也是两条路径，不能给API地址“上传书籍就训练”。

SFT需要专家审核的输入→期望结果，建议先积累约1000条高质量独立样例；这是参考百炼当前数据建议的规划目标，不是模型有效性的保证。数据含正常、缺失信息、拒绝/转人工、反例纠正和带出处建议，避免大量模板同义改写撑数量。JSONL messages格式；只训练最终任务输出与可核对依据，不要求教师提供隐式思维链。

数据按原始场景/家庭/来源分组去重，再划分训练/验证/独立测试；同一场景的改写不跨集合。冻结测试集及其答案不参与训练和挑选提示词。保留通用API＋相同RAG作为基线，SFT必须在盲测中提高领域得分并且不降低边界、事实、引用或通用能力，才替换主模型。

如果后续有上百对经教师裁定的好/坏回答，可研究DPO以改善表达偏好与边界，但不把模型批量自动打分当人类偏好。MVP不安排CPT或强化学习：目前资料量与可验证奖励不足。具体训练工作应在数据审批、基座支持和预算确定后单独立项。

## 9 推荐实施节奏

以下为一个前端、一个后端/AI开发者且有领域审核者可配合时的4个工作包估算；不把等校内材料的时间算作已承诺工期。

| 工作包 | 主要交付 | 完成门槛 |
|---|---|---|
| 第1周 基线与P0 | 固化当前版本、迁移契约/状态、修复丢稿与错误回退、双模型适配与密钥预检 | 关键交互E2E通过，正常/失败/取消有确定状态，模型ID及参数真实调用验证 |
| 第2周 知识与回答 | 10—20张审核知识卡、事实清单、来源绑定、场景提示词、E1/E2 | 引用可追溯，知识缺失不编造，常见错误样本得到定位修正 |
| 第3周 前端与评测 | 完成原型稿P0—P6/E1/E2、桌面/移动布局、100例冻结评测、候选盲评 | 无丢稿/误复制、所有已知P0关闭，工程指标与领域评分达标 |
| 第4周 试用与交接 | ≥6次辅导员演练、中心审核、整改复测、运行/知识维护说明 | 问卷通过、中心确认、复测通过，真实试点的数据规则另行确认 |

先推进第1工作包；领域资料整理可同时开展。若校内流程未拿到，继续完成公开方法与虚构场景的可用性MVP，明确标注依据限制，不虚构本校制度。

## 10 需要提供的资料

优先级1：可开放的学校流程与审核口径、3—5个虚构场景的理想要点/不能说的话、模型账号地域与可用ID以及安全保存的key路径。

优先级2：教师审过的20—30个代表性场景、推荐书目标章节的授权范围或教师自写笔记、常见家长问法的充分概括版本。

优先级3：持续积累的“原回答→教师修改→修改原因”配对数据，达到足量且评测确有收益需求时准备SFT/DPO。填写模板见 ../research/模型资料准备模板.md。
