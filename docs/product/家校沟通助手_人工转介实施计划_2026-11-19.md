# 家校沟通助手人工转介实施计划

2026-11-19 · 讨论稿

## 1. 目标与范围

在家校工作台首页主区域新增显眼的「人工转介」入口。保留顶栏和现有各模块的「人工协助」按钮、结果提示及返回路径。首页让辅导员随时查到校内协助方式，业务模块在遇到具体情况时仍就地提示，并打开同一份转介指引。

评估对象是**辅导员正在处理的学生情况或家校沟通情境**。框架回答的是「我现在是否需要找校内人员协助、先找哪一类人员」，最终的安全研判、保密例外和正式转介由有职责的人员按校内流程决定。

11 月 12 日组会提出危机场景引导至校内专业渠道，11 月 16 日会议提出核实危机识别标准、紧急程度和人工介入流程。现有代码已能在部分场景提示人工核实并停止模型拟稿，主要缺口是首页主入口、可用的校内路径，以及覆盖紧急情况、专业咨询和普通沟通困难的统一规则。[11 月 12 日组会妙记](https://nankai.feishu.cn/minutes/obcn685873d8q521e8o4w55r?from=ai_minutes) · [多 Agent 首期实施与验收](../development/多Agent首期实施与验收.md)

## 2. 入口与使用流程

| 位置 | 用户能做什么 | 实施要求 |
| --- | --- | --- |
| 首页「家校工作台」标题下、Agent 卡片区上方 | 一步打开「人工转介」，直接查看校内协助方式，也可选择「判断下一步」 | 独立于 Agent 入口显示。页面已加载时，模型故障、健康检查连接异常或 Agent 停用均不影响查看指引 |
| 全局顶栏「人工协助」 | 随时打开指引 | 保留原按钮。首页用通用指引，业务页仅使用当前有效的模块状态 |
| 学生信息分析 | 在「转由人工核实」提示中直接进入对应指引 | 保留模块内按钮。转介界面不带入粘贴原文、文件内容或学生身份 |
| 家校沟通助手 | 从结果页已有人工核实提示、后续步骤和出错时的入口打开指引 | 保留原位置和原有暂停行为，按当前状态显示安全核实、披露核对或普通协助建议 |
| 其他现有入口及场景演练 | 现有入口继续可用；演练中的表达可继续参与复盘 | 虚构对话及评分与实际转介分开，演练文字和分数不自动触发真实转介 |

转介面板先显示「现在需要人工协助」与已核准的联系路径，再显示可选的「判断下一步」。直接联系始终可用，无需填表或等评估结果。关闭后返回原页面和触发按钮，保留已录入内容。外部入口只在辅导员点击时打开；点击仅表示打开渠道，实际联系和接收由人工确认。

## 3. 辅导员转介评估框架

采用**按下一步行动分流**的短清单。问题以结构化选项呈现，每题允许「有 / 未发现 / 不清楚」或相应的「本人观察 / 当事人自述 / 他人转述 / 来源待核实」。不清楚单独保留，不能当成已经排除。按以下顺序先看当前安全，再看是否超出常规沟通、需要专业人员接手。

| 评估维度 | 界面需要核对什么 | 如何影响建议 |
| --- | --- | --- |
| 当前安全与时效 | 辅导员是否已观察到当前人身安全受到威胁，或明确认为需要立即找人协助？线索是正在发生、近期还是既往？ | 辅导员确认需要立即处理时，直接显示校内应急路径，跳过其余问题 |
| 信息来源与可核实性 | 是本人观察、学生直接表达、他人报告，还是培训引用、否定句或既往叙述？相关情况现在能否核实？ | 现实安全线索未核实，优先请人工核实。引用、否定和既往情况保留语境，不能只凭词语宣布正在发生的危险 |
| 变化与影响 | 近期困扰是否持续或明显加重，学习、生活等日常功能是否明显受影响，常规支持能否继续？ | 可作为请专业人员协助的依据。单一表现不用于作出诊断 |
| 求助需求与现有支持 | 学生是否主动希望获得专业帮助，已有专业人员是否在跟进，辅导员能否联系到相关支持人员？ | 用于选择联系对象。已有支持、学生暂不愿求助等情况不能抵消当前安全线索 |
| 职责和披露边界 | 是否涉及保密、家长告知、专业判断，或辅导员难以在现有职责内继续处理？ | 按问题性质联系院系负责人或心理健康教育中心。明确的安全问题优先于沟通和披露核对 |

| 优先顺序及行动 | 候选触发条件 | 页面结果 |
| --- | --- | --- |
| 1. 立即走校内应急流程 | 辅导员主动选择「当前需要立即协助」，或符合校方确认的明确、当前安全触发条件 | 首屏显示校方核准的应急主渠道、非工作时段或无法联系时的备用路径。当前记录转人工，不继续分析或生成家长底稿 |
| 2. 联系专业人员核实或会商 | 有现实安全线索但紧急程度或事实不清楚；或持续恶化、明显日常功能受影响、学生主动求助、涉及辅导员职责外的专业或披露判断 | 显示需要核实的事项和对应校内渠道。涉及安全疑虑时沿用 `manual_review`，暂停本次拟稿；普通会商或披露疑问保留现有提醒逻辑，具体暂停条件由校方确认 |
| 3. 按常规沟通处理或向院系咨询 | 已知情况主要是事实待补、沟通安排或普通意见分歧，当前没有发现需要升级的线索 | 显示「可继续核实情况或准备沟通」和院系协助入口。避免显示「安全」「无需转介」等保证。辅导员可随时主动升级 |

空白、尚未作答或仅有笼统描述时，显示「信息不足，暂无法给出行动建议」及人工入口；已有未核实的现实安全线索则走第 2 条。冲突时优先处理安全问题，辅导员可向上升级。评估结果显示**建议行动、触发原因、待核实项、联系路径**四部分。不同动作只是对当下校内流程的建议，不转换成高、中、低风险分数。

老师提供的《危机评估的标准》第 1 页含专业评估项目及计分示例，供中心审核时参考。本项目可借鉴其对当前情况、变化和支持资源的关注，临床项目、风险分级和阈值交由专业人员掌握。NICE NG225 第 1.6 节也建议聚焦安全需要与所需支持，避免用分值或笼统风险等级预测自伤或决定服务资格。该指南用于解释产品设计，具体的校内分流口径由学校确认。[教师资料专业边界记录](../research/教师资料候选知识_专业边界.md) · [NICE NG225，第 1.6 节](https://www.nice.org.uk/guidance/ng225/resources/selfharm-assessment-management-and-preventing-recurrence-pdf-66143837346757)

## 4. 技术与信息流转

- **复用界面。** 在 `AgentHome.tsx` 增加首页入口，由 `App.tsx` 打开扩展后的 `Assistance` 面板。区分首页主动打开、分析/底稿触发、一般协助三类来源。从模块打开时只传当前版本的状态和可解释的原因类别，过期结果不作为新记录的评估依据。
- **第一版使用结构化输入和固定规则。** 清单在页面内给出可解释建议，不把新输入发给模型。模型或文本匹配可保留为现有模块的人工核实提示，不能独立判定紧急程度或解除提示。分析、原表单和复核后生成共用服务端安全规则。后续如需处理语义和语境，应先用中心标注的合成场景离线对照，再决定是否启用。
- **保住暂停边界。** 有当前记录的业务页按会话和输入版本维护安全状态。辅导员主动标记需立即协助时，只在当前业务会话传递状态和版本，供服务端停止该版本的生成，前端同步停用复制。首页无当前记录时只提供行动指引。已有编辑可保留为过期内容；旧请求迟到不得恢复可发送状态。关闭面板、返回或修改清单不能取消已有的 `manual_review`。继续办理依据校内人工核实结论和当时有效的信息。
- **共享已审核的渠道。** 维护一份校内渠道配置，字段包括用途、适用校区或人员、服务时段、主渠道、备用渠道、审核人和核验日期。把普通预约、院系咨询与应急联系分开展示。渠道缺失、过期或打开失败时，显示校方确认的备用指引。南开大学公开页面可作为查找服务的参考，辅导员专用应急联系顺序及非工作时段渠道须由校方确认。[南开大学心理健康教育与服务](https://xgb.nankai.edu.cn/news/content/id/875.html)
- **减少敏感信息。** 首页无需输入姓名、学号或个案原文，清单状态仅在本次页面内使用。打开官方入口不附带个案内容或评估结果，也不自动发通知、提交转介单或联系家长。日志如需记录功能使用，只用来源页、动作类别、配置版本及错误状态。正式转介由辅导员在学校现有渠道发起；交接材料、记录和回执按校内确认的流程办理。[校内数据与日志规则](../handoff/工作包5_访问数据与日志规则.md)

## 5. 实施顺序与交付

| 阶段 | 可直接做的工作 | 交付或启用条件 |
| --- | --- | --- |
| 1. 首页及指引 | 加首页入口，复用转介面板，逐一核对顶栏、分析、沟通结果和异常入口。用通用指引和示例配置跑通 | 首页和各原入口均可打开，移动端可用，关闭后保留原工作。新增转介功能可单独回退，现有人工核实提示继续可用 |
| 2. 评估和规则 | 开发可跳过的短清单，输出行动与理由。用虚构场景验证紧急直达、歧义转人工和普通咨询。同步给中心审阅候选规则 | 交付评估清单、优先级表、规则版本及逐例记录。新自动分流规则经中心确认后才用于校内业务，既有安全分支持续保留 |
| 3. 校内路径接通 | 用真实、经核准的校内渠道替换示例配置，核对人员范围、主备渠道、时段、失效文案和记录责任 | 中心和院系确认触发口径，平台负责人联验路径与权限。用虚构案例验证通道可达和备用路径，再按已批准范围启用 |

可并行推进前端入口和中心口径确认。**首个开发交付**是「从首页或任一现有入口打开人工转介 → 可直接查看指引 → 可选做情境判断 → 返回原工作」。在校内应急路径确认前，以现有校内流程提示和演示配置验证，不把普通咨询预约标成应急渠道。

## 6. 验收与维护

按中心审核的虚构案例逐条标注「预期行动、是否暂停底稿、应显示的渠道、说明理由」。项目组从首批测试中分别记录紧急案例漏提示、普通案例误升级、歧义案例去向，以及继续拟稿应停止却未停止的情况。紧急样本漏提示、继续出稿或展示错误应急渠道均挡住启用。样本结果用于产品回归，不作为临床准确性的证明。

| 验收场景 | 通过条件 |
| --- | --- |
| 首页直达及既有入口 | 桌面、窄屏和键盘操作可用；模型服务异常时已加载的首页仍可查指引；原各处按钮和提示逐项通过回归 |
| 明确需要立即协助 | 无需答完清单即可打开主、备用路径，当前记录的分析、生成和复制按安全状态停止，迟到响应不覆盖该状态 |
| 现实安全线索尚待核实 | 显示人工核实路径，不因缺少完整信息退回普通沟通，也不显示已确定紧急程度 |
| 培训引用、否定语境、既往记录 | 覆盖原冻结例 FS06、FS07 及新增的时间语境；按中心标注显示适当指引，关键词命中不直接宣告紧急；模拟和复盘可照常完成 |
| 普通沟通、保密疑问或信息不足 | 分别显示补充事实、核对披露或找院系协助的建议；能随时主动打开人工入口 |
| 链接失效、返回与回退 | 失效时能找到已核准的备用指引；返回原页不丢录入；回退新评估后原有人工核实仍可用；链接、请求和日志均无个案正文 |

| 责任方 | 要确认或交付的内容 |
| --- | --- |
| 心理健康教育中心与院系负责人 | 审核题项、紧急触发、人工核实条件、披露例外、正常与应急渠道及备用路径；明确谁负责接收和后续跟进 |
| 产品与辅导员代表 | 核对首页可见性、入口命名、提示文案和关键信息是否便于当场使用 |
| 开发与评测 | 完成共享面板、规则、失败回退和逐例验收，保存规则及渠道版本 |
| 校方平台及渠道维护人 | 在实际环境验证访问路径和权限，定期复核渠道及服务时段，确认失效后的替代入口 |

校内审核重点是四项：**何时直接走应急路径、何时请专业人员核实、哪个官方入口负责接收、联系不上时走哪条备用路径**。以现有交接清单为底稿，记录确认人、日期和有效版本。教育部指导纲要提出健全校内危机预案与专业转介机制，具体执行以学校确认的流程为准。[待确认事项与交接清单](../handoff/待确认移交清单.md) · [已有待整改场景](../handoff/工作包4_待整改清单.md) · [教育部《高等学校学生心理健康教育指导纲要》](https://www.moe.gov.cn/srcsite/A12/moe_1407/s3020/201807/t20180713_342992.html)
