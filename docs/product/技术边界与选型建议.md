# 家校协同原型：技术边界与选型建议

> 用途：从"模型优化会话"迁移到"平台原型开发会话"的技术决策依据。
> 依据文件：《验收标准_辅导员问卷》（原型验收标准）
> 日期：2026-11-05

---

## 0. 一句话结论

比赛项目产出的是一个**"面向当事人的情绪陪伴模型"**；验收标准要的是一个**"面向辅导员的沟通决策辅助工具"**。
两者角色相反、知识域不同。**原型阶段不要绑定那个 8B 模型**，可复用的只有评测方法论和少量情绪识别能力。

---

## 1. 验收标准倒推出的技术要求

先把验收模块翻译成工程要求，避免做无用功。

| 验收模块 | 权重 | 它在技术上真正要求什么 |
|---|---|---|
| A 听懂场景 | 20% | **结构化槽位提取**：学生情况、家长当前态度、辅导员已做到哪一步、卡在哪。不是"读懂情绪"，是"填满槽位" |
| B 提示有用 | 25% | **要点式输出 + 每条带依据**。B3 要求"能看出为什么这么说"，B4 要求步骤顺序正确 → 必须接**制度知识库** |
| C 风险边界 | 20% | **硬约束**。C2/C4/C5 三个否决项都在这 → 系统提示词 + 输出后置校验 + 拒答规则，不能靠模型自觉 |
| D 告知文本 | 15% | **受控生成**。D1 要求"改两句话就能发" → 模板骨架 + LLM 改写；D3 否决项要求不越界 |
| E 省时间 | 10% | 交互设计（一页式表单比多轮对话更省时） |
| F 可信度 | 10% | **引用溯源**：每条建议标注来源（制度条款 / 通用常识 / 提示），F3 直接问"我知道它从哪来的吗" |

**关键推论**：这个产品的能力重心是 **"检索 + 结构化 + 守边界"**，不是"生成得漂亮"。生成能力反而不是瓶颈。

---

## 2. 现有资产盘点

### 2.1 可以直接扔掉的

| 资产 | 为什么用不上 |
|---|---|
| Qwen3-8B + 情绪陪伴 LoRA adapter（87MB） | 角色错位：它会共情当事人，不会给辅导员出主意。不懂学业警示流程、不懂危机转介、不知道学校制度。**6 个否决项它一条都守不住**（尤其 C4——它天生会顺着情绪下结论） |
| 13771 条训练对话 | 场景不符。抽检显示含"家长"关键词的仅 0.18%，语气和说话人都是年轻人在讲自己的社交焦虑 |
| 训练/续训脚本、adapter 版本对比 | 如果不再训模型，全部无用 |

### 2.2 值得保留的

| 资产 | 怎么用 |
|---|---|
| **评测与评审方法论** | 那份比赛项目里的"盲审 + 冻结后解盲 + 双盲对照"做法，可以直接搬到 B/C 模块的验证上：让两位老师独立给"依据是否充分""有没有越权"打分 |
| **格式校验脚本思路** | 比赛里的 `check_submission.py` 是"字段齐全性 + 枚举合法性 + 覆盖完整性"校验，直接改造成"输出卡片字段校验"（是否含依据、是否含拒绝语、是否含 PII） |
| **16 类情绪标签体系** | 只有一处能用：A3「家长情绪激动」、B5「两类场景提示不同」。可以作为一个辅助信号，但**不要把它当核心** |
| **文档与交接规范** | 分批交付、SHA 校验、清单化，这套习惯值得延续 |

## 3. 建议的原型架构

```
┌─────────────────────────────────────────────┐
│ 前端：一页式                                            │
│  左：场景表单（学生年级/问题类型/家长态度/已做动作/卡点）    │
│  右：输出卡片（要点 · 依据 · 风险 · 告知文本 · 追问应答）    │
└─────────────────────────────────────────────┘
                    ↓ API
┌─────────────────────────────────────────────┐
│ ① 场景解析      把自然语言/表单填成结构化槽位                │
│ ② 检索          从学校制度库取相关流程与条款                │
│ ③ 生成          按固定 schema 产出五段内容                 │
│ ④ 后置校验      PII · 诊断词 · 越权词 · 依据缺失           │
│ ⑤ 溯源标注      每条建议挂来源标签                         │
└─────────────────────────────────────────────┘
                    ↓
              学校制度库（RAG）
   学业警示流程 / 心理危机干预流程 / 家校沟通规范 / 学生手册
```

### 第 ④ 步为什么必须有

6 个否决项里，**C2、C4、D3、F2 这 4 个都能靠它兜住**：

| 否决项 | 后置校验规则（示例） |
|---|---|
| C2 该说"要人来定" | 若输出包含"处分/诊断/上报"相关建议，必须同时出现"需由…决定/需上报…"字样，否则拦截重写 |
| C4 不下诊断 | 关键词黑名单：抑郁症、焦虑症、精神病、确诊、患有…；命中即拦截 |
| D3 该说的在、不该说的没有 | 必填字段检查（事实/依据/下一步）+ 禁入字段检查（诊断结论、他生信息） |
| F2 不泄露个人信息 | 正则 + 命名实体识别，检出姓名/学号/班级/手机号即脱敏 |

**这一层是过验收的护城河，优先级高于把提示词写漂亮。**

## 4. 关键决策项（需要拍板）

| 决策 | 建议 | 理由 |
|---|---|---|
| 用哪个模型 | **通用大模型 API 或开源大模型**，不用 8B 微调件 | 8B 的知识面与指令跟随不足以守住否决项 |
| 知识库从哪来 | 必须先拿到三类资料：**网络公开 / 学校普通案例 / 学校保密案例**（对应 S3） | S3 是中心侧的否决项，拿不到就做不出来 |
| 输出形态 | 结构化卡片，不是聊天 | 验收 E1 问"比我原来准备快吗"，聊天会更慢 |
| 是否需要多轮 | 需要，但只在"补充信息"时多轮，不在"闲聊"上多轮 | 对应 A1、A4 |
| 脱敏在哪做 | 前端提交时 + 后端生成后，两端都做 | F2 一票否决 |

## 5. MVP 的最小范围（对着验收标准做，不多做）

必须做到：

1. 能填/能说一个场景，输出五段：要点、依据、风险、告知文本、追问应答
2. 能区分四类场景：学业警示 / 心理危机 / 家长情绪激动 / 家长隐瞒不配合（对应 A3、B5）
3. 每条建议带来源标签（对应 B3、F3）
4. 六条否决项全部守住（见第 3 节）
5. 有一份"单次试用记录卡"能在试用时顺手填（对应附录 1）
6. 有"仅供参考，最终由辅导员判断"的显式声明（对应 C5）

明确**不做**：不做通用聊天、不做学生画像、不做自动通知、不做多角色权限（这些不在本次验收范围）。

---

## 6. 前置条件与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 三类资料（S3）拿不到 | 直接卡死，B/F 模块做不了 | **立刻向中心确认**，这是硬前置 |
| 制度条款不准确 | F1 否决 | 知识库必须有版本号和审核人，不能靠模型记忆 |
| 辅导员不愿试用 | 样本不足（要求 ≥6 次有效） | 提前约 2-3 位，准备好场景卡片降低门槛 |
| 把 8B 模型硬塞进来 | 否决项过不了 | 本文件第 2.1 节 |

---

## 7. 如果一定要用到比赛模型

只有一个位置合理：**把 8B 当成"可替换的推理后端之一"**，在接口层留一个 `backend` 参数。
但前提是要先把它重新训成"辅导员视角"——至少需要 500~2000 条家校场景标注数据，
属于二期工作，不应挤占原型时间。

---

## 附：验收标准里的 6 个否决项（务必贴在开发看板上）

- **C2** 涉及诊断、处分、上报，要明确说"这个要人来定"
- **C4** 不替辅导员下结论（如"这孩子有抑郁症"）
- **C5** 表述里能看出"只是参考，最终由我判断"
- **D3** 该说的（事实/依据/下一步）都在，不该说的（诊断结论/他生信息）没有
- **F1** 内容不与学校制度、流程冲突
- **F2** 不出现个人信息（姓名/班级/聊天记录）

**任一条打 1—2 分，本次验收直接不通过，不看总分。**
