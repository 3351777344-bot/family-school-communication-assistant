# 辅导员线上试用流程

新版工作台请使用[工作包 4 演练与验收手册](工作包4_演练与验收手册.md)。下文保留旧 HTML 演示版的试用流程。

## 试用目标

先评估工作台是否好理解、输出是否便于核对，再评估接入模型后的内容质量。离线演示版只显示固定示例；模型版会把脱敏后的表单发送到配置的外部模型服务。平台权限、服务方留存和日志规则尚待确认。

## 会前准备

- 发送 `app/家校沟通助手_演示版.html` 与 `docs/trial/辅导员试用说明_3分钟.docx`。
- 准备一张项目组编写的虚构场景卡，不使用真实个案或咨询原话。
- 若准备模型版对照，向试用者说明文本会发送至配置的模型服务；只使用虚构输入，且不向试用者分发 API key。
- 核实危机场景仍处于待确认状态，不把它作为可用的研判功能演示。

## 会中 12 分钟

1. 说明这不是对辅导员的考核，只记录界面卡点、流程理解和内容修改量。
2. 请辅导员使用虚构场景卡亲自填写离线演示版。观察字段是否清晰、是否理解各结果区和人工确认边界。
3. 如做模型版对照，由项目组在明确说明数据流后，用同一张虚构场景卡操作；不得复制教师的真实工作材料。
4. 询问：哪条表达不符合工作习惯？流程顺序哪里不合适？底稿需要修改几处？是否看懂引用来源和人工核对提示？
5. 用单次试用记录卡记录完成时长、修改量、是否愿意采用和明显误导项。

## 试用后

按验收问卷记录结果。验收样本目标为 2—3 位辅导员、每人 2—3 次虚构或充分合成的场景演练，有效样本至少 6 次。中心侧确认与辅导员可用性验收分别记录。

未确认校内数据政策、模型服务方处理规则前，不以真实个案试用、不部署到公网或校内多人环境，也不打包 API key。
